# Monster Slayer — Plan rozwoju v4.0 (pivot: idle-ARPG)

> Dokument roboczy. Zastępuje warstwę strategiczną GDD v3.0.
> GDD v3.0 pozostaje ważny dla: combat feel, art direction, ECS, stack.
> Ten dokument zmienia: **model retencji, progresję, monetyzację i roadmapę**.

## 0. TL;DR — co się zmienia

| | GDD v3.0 (ARPG akcji) | v4.0 (idle-ARPG) |
|---|---|---|
| Sesja gracza | 30–60 min aktywnej gry | 3–8 min × 4–6 razy dziennie + tło |
| Źródło głębi | ręcznie robione poziomy | generatywna progresja + buildy |
| Content/godzinę pracy dev | niski | **bardzo wysoki** |
| Retencja D7 | zależy od ilości contentu | zależy od pętli (tanie do naprawy) |
| Monetyzacja | brak modelu | jednorazowy unlock + sezon kosmetyczny |
| Ryzyko regulacyjne (DFA) | wysokie przy gachy | **zerowe** |
| Kanał dystrybucji | brak | r/incremental_games → itch → Steam |

**Co zostaje bez zmian:** PixiJS v8, ECS w TypeScript, Svelte 5 HUD, Elixir/Phoenix.
Stack jest trafiony. Zmienia się to, co na nim budujesz.

**Zdanie definiujące projekt:**
> Przeglądarkowy hack'n'slash, w którym postać walczy dalej, kiedy zamkniesz kartę —
> a wracasz po to, żeby podjąć decyzję o buildzie, nie żeby klikać.

## 1. Filary designu

Każdy feature musi obsługiwać przynajmniej jeden filar. Jeśli nie obsługuje — do backlogu.

### F1. Czas gracza jest święty
Gra nie karze za nieobecność. Nagradza powrót.
Zero timerów wymuszających „wróć o 19:00". Zero energii. Zero daily reset streak, który się łamie.
→ *Uzasadnienie: to jedyny model, w którym solo dev bez UA utrzymuje graczy latami.*

### F2. Decyzja > klikanie
Wartość sesji leży w wyborze (build, priorytet, respec), nie w liczbie kliknięć.
Każda automatyzacja, którą odblokujesz, jest **nagrodą**, nie utratą gameplayu.

### F3. Głębia jest generatywna
Content robi kombinatoryka: statystyki × modyfikatory × drzewko × unikaty × wyzwania.
Ręcznie robisz tylko: bossów, sylwetki wrogów, kamienie milowe.

### F4. Build jest treścią do udostępnienia
Ekran postaci ma być czymś, co gracz sam z siebie wkleja na Reddita.
To jest twój kanał marketingowy. Projektuj pod screenshot i pod kod builda.

### F5. Uczciwość jako feature
Ceny w realnej walucie. Zero losowych zakupów. Zero pay-to-win.
→ Nie tylko etyka: to gwarantuje, że nie przepisujesz gry po wejściu DFA.

## 2. Architektura pętli retencji

Retencja to **zagnieżdżone pętle w różnych skalach czasu**. Brak którejkolwiek = odpływ dokładnie w tej skali.

```
┌─ 30 dni ── PRESTIŻ / ASCENSJA ─ trwały mnożnik, reset postępu
│  ┌─ 7 dni ── NOWA STREFA / KLASA / SEZON
│  │  ┌─ 24 h ── OFFLINE PROGRESS + dzienna decyzja o buildzie
│  │  │  ┌─ 20 min ── AWANS TIERU / nowy modyfikator
│  │  │  │  ┌─ 2 min ── MINI-BOSS / czyszczenie strefy
│  │  │  │  │  ┌─ 5 s ── cios → damage number → drop
```

### 2.1 Mapa pętli — specyfikacja

| Skala | Trigger | Nagroda | Metryka, na którą wpływa |
|---|---|---|---|
| **5 s** | trafienie, crit, drop | hit-stop, damage number, dźwięk, screen shake | sesja, „feel" |
| **2 min** | wyczyszczenie fali / mini-boss | skok DPS, item, fragment | długość sesji |
| **20 min** | awans tieru strefy | odblokowanie modyfikatora / receptury | D1 |
| **24 h** | powrót do gry | **ekran offline progress** | **D1 → D7** |
| **7 dni** | odblokowanie strefy / klasy | nowy zestaw mechanik | D7 → D30 |
| **30 dni** | prestiż | trwały mnożnik + nowa warstwa systemów | D30 → LTV |

### 2.2 Ekran powrotu (najważniejszy ekran w grze)

To jest miejsce, gdzie wygrywa się D7. Specyfikacja:

```
┌────────────────────────────────────┐
│  Nieobecność: 7 h 42 min           │
│                                     │
│  ⚔  Zabici:        14 302          │
│  💰 Złoto:         +2,4 M          │
│  📦 Przedmioty:    38 (2 rzadkie)  │
│  📈 Najgłębsza strefa:  47 → 51    │
│                                     │
│  ⚠ Utknąłeś na strefie 51          │
│     Powód: za mało obrażeń obszar. │
│     [Pokaż sugestię buildu]        │
│                                     │
│  [ODBIERZ]                          │
└────────────────────────────────────┘
```

Trzy rzeczy, które ten ekran **musi** robić:
1. **Konkretne liczby** — nie „zebrano nagrody", tylko `14 302 zabitych`.
2. **Diagnoza blokady** — powiedz dlaczego gracz utknął. To zamienia frustrację w cel.
3. **Jedna sugerowana akcja** — przycisk, który prowadzi do decyzji, nie do menu.

**Anty-wzorzec:** nie rób z tego reklamy („obejrzyj film ×2"). Zabija to filar F1 i F5.

## 3. Drabina odblokowań (onboarding → 20 h)

Zasada nadrzędna: **zapowiadaj każde odblokowanie zanim będzie dostępne.**
Wyszarzona ikona z napisem „Kuźnia — poziom 12" ciągnie gracza. Niespodzianka nie ciągnie.

### Faza A — 0–30 min: „umiem bić"
- Zero tutorialu tekstowego. Wchodzisz, jest wróg, jest przycisk.
- Jeden stat: **Obrażenia**. Jedno źródło waluty: **Złoto**.
- Pierwszy upgrade po ~20 sekundach. Drugi po ~40. Trzeci po ~70.
- **Cel:** gracz ma poczuć skok mocy trzy razy zanim zdąży pomyśleć o wyjściu.

### Faza B — 30 min–2 h: „mam wybór"
- Pierwsza umiejętność aktywna (cooldown, nie zasób).
- Boss strefy 10 → blokuje przejście, wymaga jednego upgrade'u. Pierwszy prawdziwy próg.
- Tiery rzadkości: Zwykły / Magiczny / Rzadki. Kolory. To jest 80% satysfakcji z lootu.
- Drugi stat: **Szybkość ataku**. Teraz istnieje pierwszy trade-off.

### Faza C — 2–5 h: „mogę wyjść" ⭐ MOMENT KRYTYCZNY
- **Odblokowanie trybu idle.** Gra jawnie mówi: „możesz zamknąć kartę".
- To jest najważniejszy komunikat w całej grze. Naucz gracza, że powrót ma sens.
- Pierwsza automatyzacja: **auto-atak**.
- Limit offline: 8 h (bazowo).

### Faza D — 5–10 h: „buduję"
- **Kuźnia**: ulepszanie, reroll afiksów, rozbiórka na materiały.
- Drzewko umiejętności z pierwszym rozgałęzieniem (2 ścieżki).
- Auto-salvage z filtrem (automatyzacja #2 — realna oszczędność klikania).
- Pierwsze **unikaty** — przedmioty, które zmieniają zasady, nie tylko liczby.

### Faza E — 10–20 h: „resetuję, żeby być silniejszym"
- **Pierwszy prestiż.** Musi przyjść szybko, bo to jest *lekcja*, nie ściana.
  Kolejne prestiże rozciągasz: 1. po ~12 h, 2. po ~8 h, 3. po ~10 h, potem rosnąco.
- Waluta prestiżu + osobne drzewko trwałych bonusów.
- Auto-prestiż jako późna automatyzacja.

### Faza F — 20 h+: „mam cel na miesiąc"
- Druga klasa (odblokowana przez postęp, nie przez płatność).
- Wyzwania (runy z ograniczeniami → trwałe bonusy).
- Sezony z rankingiem.
- Druga warstwa prestiżu (Ascensja).

### 3.1 Drabina automatyzacji — osobna lista

Każda automatyzacja to nagroda. Kolejność ma znaczenie:

| # | Automatyzacja | Odblokowanie | Co eliminuje |
|---|---|---|---|
| 1 | Auto-atak | ~2 h | klikanie ataku |
| 2 | Auto-podnoszenie | ~3 h | klikanie lootu |
| 3 | Auto-salvage z filtrem | ~6 h | zarządzanie plecakiem |
| 4 | Auto-postęp strefy | ~8 h | ręczne przechodzenie |
| 5 | Auto-użycie umiejętności | ~12 h | rotacja |
| 6 | Auto-ekwipunek (wg wagi statów) | ~20 h | porównywanie itemów |
| 7 | Auto-prestiż (z progiem) | ~40 h | ręczny reset |
| 8 | Auto-ekspedycje | ~60 h | mikrozarządzanie |

**Zasada:** nigdy nie automatyzuj decyzji o buildzie. To jest jedyna rzecz, której gracz nie ma oddać.

## 4. Matematyka progresji

To jest sekcja, którą najłatwiej zepsuć i najdrożej naprawić. Tuning tutaj = cała odczuwalna jakość gry.

### 4.1 Koszty ulepszeń — krzywa wykładnicza

```
C(n) = C₀ · r^n
```
- `C₀` — koszt pierwszego poziomu
- `r` — współczynnik wzrostu, **1.07–1.12**
- `r < 1.07` → gracz kupuje wszystko, brak decyzji
- `r > 1.15` → ściany, frustracja

Koszt zakupu poziomów od `n` do `n+k` (potrzebne do przycisku „kup ×10 / max"):
```
C(n → n+k) = C₀ · r^n · (r^k − 1) / (r − 1)
```

**Odwrotność — ile poziomów stać gracza za `G` złota** (to jest funkcja, której potrzebujesz do „kup max"):
```
k = floor( log( 1 + G·(r−1)/(C₀·r^n) ) / log(r) )
```

Wartości startowe do tuningu:
| Upgrade | C₀ | r | efekt/poziom |
|---|---|---|---|
| Obrażenia | 10 | 1.09 | +2 flat, ×1.01 |
| Szybkość ataku | 50 | 1.12 | +1.5% |
| Szansa na crit | 200 | 1.14 | +0.25% (cap 60%) |
| Mnożnik crit | 150 | 1.11 | +3% |
| Znaleźne złoto | 80 | 1.10 | +2% |

### 4.2 Skalowanie HP wrogów

Klasyczny błąd: liniowe HP → gracz miażdży wszystko po 2h. Drugi błąd: czysto wykładnicze → ściana.
Rozwiązanie: **wykładnicze z korektą wielomianową**.

```
HP(z) = HP₀ · z^2.2 · 1.16^z
```
gdzie `z` = numer strefy.

Boss co 10 stref: `HP_boss = HP(z) · 12`

**Docelowe tempo:** gracz „na czysto" przechodzi strefę w ~25–40 s w fazie aktywnej.
Kiedy czas przekracza ~90 s → to jest sygnał progu → to jest moment, w którym pokazujesz sugestię buildu.

### 4.3 Prestiż

```
PP = floor( K · sqrt( total_gold_earned / T ) )
```
- `K` ≈ 20, `T` ≈ 1e9 (tuning)
- Pierwiastek jest kluczowy: **każdy kolejny PP kosztuje coraz więcej postępu**, ale nigdy nie jest niemożliwy.

Efekt PP: `mnożnik = 1 + 0.02 · PP` na starcie, plus wydawanie PP w drzewku trwałym.

**Warunek dobrego prestiżu:** pierwszy reset musi pozwolić dojść do poprzedniego punktu w **~30–40% czasu**. Jeśli wolniej — gracz czuje karę. Jeśli szybciej — resety są bez znaczenia.

### 4.4 Warstwy prestiżu

| Warstwa | Nazwa | Odblokowanie | Resetuje | Daje |
|---|---|---|---|---|
| 1 | Prestiż | ~12 h | poziomy, złoto, strefy | PP → drzewko trwałe |
| 2 | Ascensja | ~60 h | PP + drzewko | Iskry → nowe mechaniki |
| 3 | Transcendencja | ~250 h | wszystko | zmiana zasad gry (nowe formuły) |

Warstwa 3 nie jest do zrobienia w roku 1. Zostaw haczyk w UI, zrób w roku 2.

### 4.5 Offline progress — obliczenie deterministyczne

**Nigdy nie symuluj.** Licz z różnicy timestampów. Odporne na exploity, tanie, natychmiastowe.

```
Δt      = min(now − last_seen, cap)
rate    = zapisane_dps_i_gold_rate_z_momentu_wylogowania
gain    = rate · Δt · efficiency
```

| Parametr | Free | Supporter |
|---|---|---|
| `cap` | 8 h | 24 h |
| `efficiency` | 0.55 | 0.85 |

**Postęp stref offline:** licz iteracyjnie, ale w pętli po strefach (nie po klatkach):
```elixir
# czas potrzebny na strefę z = HP(z) / dps
# odejmuj od budżetu czasu aż zabraknie
```
Koszt: kilkadziesiąt iteracji, nie miliony. O(liczba_stref).

**Anty-exploit:** `last_seen` ustawiany **wyłącznie serwerowo**. Zegar klienta nigdy nie dotyka tej wartości.

### 4.6 Afiksy przedmiotów

Item = baza + N afiksów, gdzie N zależy od rzadkości:

| Rzadkość | Afiksy | Waga dropu | Kolor |
|---|---|---|---|
| Zwykły | 0–1 | 70% | szary |
| Magiczny | 2 | 22% | niebieski |
| Rzadki | 3–4 | 7% | żółty |
| Epicki | 4–5 + 1 unikalny mod | 0.9% | fioletowy |
| Unikat | stały zestaw + efekt zmieniający zasady | 0.1% | pomarańczowy |

Wartość afiksu skaluje się z poziomem strefy dropu:
```
wartość = base · (1 + 0.08·z) · roll(0.7, 1.0)
```
`roll` widoczny dla gracza jako procent jakości — to jest paliwo do rerollowania w kuźni.

## 5. Systemy — specyfikacja

### 5.1 Walka

Tryb hybrydowy — to jest kluczowa decyzja architektoniczna:

| Tryb | Kto liczy | Co widzi gracz |
|---|---|---|
| **Aktywny** (karta otwarta, focus) | klient (ECS + PixiJS), serwer waliduje statystycznie | pełna animacja, damage numbers, efekty |
| **Tło** (karta w tle / blur) | serwer, formuła zamknięta | pasek postępu, licznik |
| **Offline** (brak sesji) | serwer przy powrocie | ekran podsumowania |

**Walidacja statystyczna zamiast pełnej autorytatywności:**
Serwer zna ekwipunek i drzewko gracza → zna `max_theoretical_dps`.
Klient raportuje postęp co 5 s. Serwer sprawdza:
```
zgłoszony_postęp <= max_theoretical_dps · Δt · 1.15   # 15% marginesu
```
Przekroczenie → flaga, nie ban. Trzy flagi → sesja przechodzi w tryb serwerowy.
To jest tanie i wystarczające dla gry bez PvP o realną wartość.

### 5.2 Ekwipunek i sloty

Broń, Hełm, Napierśnik, Rękawice, Buty, Pas, Amulet, 2× Pierścień = **9 slotów**.
Loadouty: 1 free, 4 dla Supportera. Przełączanie bez kosztu.

### 5.3 Kuźnia

| Akcja | Koszt | Efekt |
|---|---|---|
| Ulepszenie (+1…+15) | złoto ↑, materiały | +% do statów bazy |
| Reroll afiksów | fragmenty | nowy zestaw afiksów |
| Reroll wartości | pył | nowe rolle w tych samych afiksach |
| Rozbiórka | — | materiały wg rzadkości |
| Transfer unikalnego moda | rzadka waluta | późna gra, bardzo drogie |

Reroll wartości (nie afiksów) to najlepszy sink — gracz goni 100% jakości i zawsze ma na co wydać.

### 5.4 Drzewko umiejętności

- ~60 węzłów w roku 1, 3 gałęzie tematyczne.
- Respec: **darmowy i natychmiastowy**. Kara za respec zabija eksperymentowanie, a eksperymentowanie to twój content.
- Węzły typu „keystone" (5–6 sztuk) — zmieniają zasady, definiują archetyp.
  Przykład: *„Twoje ataki nie mogą trafiać krytycznie. Zamiast tego +250% obrażeń bazowych."*
  Keystone'y są tym, o czym ludzie piszą na Reddicie.

### 5.5 Wyzwania

Runy z ograniczeniem, dające trwały bonus po ukończeniu.
- „Bez ekwipunku do strefy 40" → +15% globalnych obrażeń na stałe
- „Jedna umiejętność" → +1 slot loadoutu
- „Tylko obrażenia bazowe" → odblokowuje keystone

Wyzwania to najtańszy content w grze: zero nowych assetów, dziesiątki godzin rozgrywki.

### 5.6 Sezony

- 8 tygodni. Świeży start, osobny ranking, sezonowy modyfikator globalny.
- Modyfikator sezonu zmienia meta: *„Wrogowie mają 50% więcej HP, ale rzadkie dropy ×3."*
- Po sezonie postać trafia do puli wiecznej. **Nic nie znika.**
- Nagrody sezonowe: **wyłącznie kosmetyczne + tytuły**. Zero przewagi mocy.

### 5.7 Bestiariusz / Kodeks

Zabij N sztuk danego wroga → trwały bonus (+% obrażeń przeciw temu typowi).
Kolekcjonerstwo jako mnożnik. Zero kosztu produkcji, silna retencja u części graczy.

### 5.8 Kod builda — mechanizm wirusowy ⭐

Serializacja pełnego builda do krótkiego stringa:
```
MS4:aXR2Zm9vYmFy...   (base64url ze skompresowanego CBOR)
```
- Wklejasz kod → widzisz build w read-only, z DPS i statami.
- Przycisk „zastosuj co się da" (respec + założenie posiadanych itemów).
- Każdy screenshot ekranu postaci ma kod w rogu.

To jest twój kanał dystrybucji. Ludzie udostępniają buildy → link prowadzi do gry.
**Zaprojektuj ekran postaci pod screenshot**: czytelny w 1200 px szerokości, kontrastowy, z widocznym DPS i nazwą builda.

### 6.1 Model

| Produkt | Cena | Zawartość |
|---|---|---|
| **Supporter** (jednorazowo) | 49 zł | cap offline 8→24 h, efficiency 0.55→0.85, 4 loadouty, 2× miejsce w skrytce, kosmetyczna aura, filtr lootu premium |

**Zero waluty wirtualnej. Zero losowości. Zero mocy za pieniądze.**

### 6.2 Dlaczego akurat tak

- DFA (propozycja Komisji przewidziana na Q4 2026) celuje w walutę wirtualną, loot boxy
  i obowiązek pokazywania realnej ceny obok ceny w walucie wewnętrznej.
  Model powyżej jest z tym zgodny **z definicji** — nie musisz nic przepisywać.
- Steam i itch nie mają problemu z jednorazowym zakupem. Z gachy — mają.
- Społeczność incremental/idle jest **wrogo nastawiona** do P2W. Jeden post o pay-to-win na r/incremental_games kończy grę.

### 6.3 Prognoza (konserwatywna)

Przy modelu jednorazowym konwersja 2–5% jest realistyczna dla dobrze ocenionej gry niszowej.

| Scenariusz | MAU | Konwersja | Śr. wartość | Przychód/mies. |
|---|---|---|---|---|
| Pesymistyczny | 2 000 | 1.5% | 45 zł | ~1 350 zł |
| Bazowy | 10 000 | 3% | 55 zł | ~16 500 zł |
| Optymistyczny | 40 000 | 4% | 70 zł | ~112 000 zł |

**To nie jest plan spłaty długu w roku 1.** Traktuj przychód z gry jako opcję o wysokiej wariancji,
a nie jako pozycję w budżecie. Pozycją w budżecie jest kontrakt.

## 7. Architektura techniczna

### 7.1 Podział odpowiedzialności

```
┌─────────────── PRZEGLĄDARKA ───────────────┐
│  Svelte 5          — HUD, menu, ekrany     │
│  PixiJS v8 + ECS   — scena walki, VFX      │
│  Web Worker        — symulacja predykcyjna │
│  IndexedDB         — cache stanu (nie SoT) │
└──────────────┬─────────────────────────────┘
               │ Phoenix Channels (WebSocket)
┌──────────────▼─────────────────────────────┐
│  Phoenix                                    │
│   ├ PlayerSession (GenServer / gracz)      │
│   ├ Registry + DynamicSupervisor           │
│   ├ Oban  — sezony, rankingi, sprzątanie   │
│   ├ ETS   — leaderboardy, hot cache        │
│   └ Ecto / PostgreSQL — źródło prawdy      │
└────────────────────────────────────────────┘
```

### 7.2 PlayerSession — rdzeń serwera

```elixir
defmodule MonsterSlayer.Game.PlayerSession do
  use GenServer, restart: :transient

  # Cykl życia:
  #  connect  → start_child → wczytaj z Postgresa → oblicz offline gain
  #  tick     → co 1 s: postęp w tle, walidacja raportów klienta
  #  persist  → co 30 s: zapis snapshotu (debounce na zmianach)
  #  idle 5 m → terminate (zapis + wyrejestrowanie)

  @tick_ms 1_000
  @persist_ms 30_000

  def start_link(player_id), do:
    GenServer.start_link(__MODULE__, player_id, name: via(player_id))

  defp via(id), do: {:via, Registry, {MonsterSlayer.SessionRegistry, id}}

  # Stan trzymany w pamięci, Postgres to checkpoint — nie ścieżka gorąca.
end
```

**Dlaczego to jest właściwe użycie Elixira (a nie naciągane):**
- 10 000 równoczesnych graczy = 10 000 lekkich procesów. Na jednym VPS-ie.
- Izolacja błędów: crash jednej sesji nie dotyka pozostałych.
- Tick w tle bez zewnętrznego schedulera.
- WebSockety to natywny przypadek użycia Phoenixa, nie dodatek.

### 7.3 Protokół klient–serwer

| Kierunek | Wiadomość | Częstotliwość |
|---|---|---|
| C→S | `progress_report` (zabici, złoto, strefa) | 5 s |
| C→S | `action` (kup upgrade, załóż item, respec) | zdarzeniowo |
| S→C | `state_patch` (delta stanu) | 5 s / po akcji |
| S→C | `authoritative_correction` | przy rozjeździe |
| S→C | `offline_summary` | przy połączeniu |

**Zasada:** klient nigdy nie wysyła „mam teraz 1e12 złota". Wysyła „zabiłem 40 wrogów w strefie 51".
Serwer sam wylicza złoto z własnych formuł.

### 7.4 Schemat bazy

```sql
players            (id, email, supporter_until, created_at, last_seen_at)
characters         (id, player_id, season_id, class, level, deepest_zone,
                    prestige_points, ascension_sparks, state_blob JSONB)
items              (id, character_id, slot, base_id, rarity, affixes JSONB,
                    quality REAL, upgrade_level INT, equipped BOOL)
skill_allocations  (character_id, node_id, points)
seasons            (id, name, modifier JSONB, starts_at, ends_at)
leaderboard        (season_id, character_id, deepest_zone, updated_at)
purchases          (id, player_id, sku, amount_pln, provider_ref, created_at)
telemetry          (id, player_id, event, payload JSONB, at)   -- partycjonowana
```

`state_blob` JSONB — celowo. Stan idle zmienia się co patch; sztywny schemat na to
byłby migracją co tydzień. Trzymaj w kolumnach tylko to, po czym filtrujesz/sortujesz.

### 7.5 Wydajność klienta

- Object pooling dla wrogów i damage numbers — **bez tego GC zabija framerate po 10 min**.
- Cap na widoczne damage numbers: 40. Reszta agreguje się w „×12".
- Przy `document.hidden` → przełącz w tryb tła, zatrzymaj rendering, zostaw logikę na serwerze.
- Cel: 60 fps przy 80 wrogach na Chromebooku z 2020. To jest twoja publika.

### 7.6 Liczby wielkie

Idle games przekraczają `Number.MAX_SAFE_INTEGER` po kilkunastu godzinach.
**Zdecyduj to w tygodniu 1, nie w miesiącu 6.**

Rekomendacja: reprezentacja `{mantysa: number, wykładnik: number}` (jak break_infinity.js),
po stronie Elixira odpowiednik jako `{float, integer}`.
Formatowanie: `1.24e15` → `1.24 Kw` (notacja krótka) z opcją przełączenia na naukową.

## 11. Backlog pomysłów (poza rokiem 1)

Posortowane wg stosunku wartość/koszt:

- **Ekspedycje offline** — wysyłasz postać na 4 h po konkretny zasób. Decyzja + nagroda za powrót.
- **Pety/towarzysze** z własną progresją i pasywkami
- **Ligi** — tygodniowe rankingi w małych grupach (100 osób), nie globalne. Globalny ranking demotywuje, mikroligi motywują.
- **Ekwipunek sezonowy** z mechanikami działającymi tylko w danym sezonie
- **Craft receptur** odkrywanych przez eksperyment (kombinacje materiałów)
- **Drzewko frakcji** — reputacja u 3 frakcji, wzajemnie wykluczające bonusy
- **Roguelite dungeon** — 20-minutowy tryb aktywny z losowymi modyfikatorami, dla graczy chcących „pograć"
- **Idle PvP asynchroniczne** — twój build vs czyjś build, symulacja serwerowa, zero pay-to-win
- **Edytor filtrów lootu** (jak w PoE) — hardkorowa publika to pokocha, koszt niski
- **Achievement points jako meta-waluta** z osobnym drzewkiem
- **New Game+ z modyfikatorami wybieranymi przez gracza**
- **API publiczne do buildów** — pozwól społeczności zbudować planner. Darmowy ekosystem.
- **Steam Workshop na skiny** — user-generated content, zero kosztu produkcji

## 12. Anty-wzorce — czego nie robić

| Anty-wzorzec | Dlaczego zabija |
|---|---|
| Energia / limity wejść | łamie F1, wypycha graczy do konkurencji |
| Daily streak z karą za przerwanie | zamienia grę w obowiązek → wypalenie → churn |
| Reklamy z nagrodą ×2 | uczy gracza, że gra jest niepełna bez reklam |
| Płatne przyspieszacze | P2W, wrogo przyjęte w niszy, ryzyko DFA |
| Loot boxy / gacha | ryzyko regulacyjne + śmierć reputacyjna na Reddicie |
| Płatny respec | zabija eksperymentowanie = zabija twój główny content |
| Wipe postępu przy patchu | jednorazowa strata zaufania, nieodwracalna |
| Content przed naprawą pętli | najdroższy błąd w całym gatunku |
